# TDD-цикл для BookCopy (SCRUM-6)

## Вимоги

Примірник повинен належати до наявної книги та мати непорожній інвентарний номер. Новий примірник отримує статус `Available`. Глобальна унікальність інвентарного номера ще не реалізована і буде забезпечена поза конструктором: у сервісі та базі даних.

## Red

На етапі Red було перевірено поточний набір усього рішення через Test Explorer:

- 28 тестів усього рішення: 23 успішні та 5 невдалих;
- у проекті `Library.UnitTests` було 27 тестів, а в `Library.IntegrationTests` — 1 шаблонний тест.

Всі попередні тести залишалися зеленими. П’ять невдалих сценаріїв стосувалися примірника:

- `null`-книга;
- порожній інвентарний номер;
- номер з одним пробілом;
- номер із декількома пробілами;
- номер із символом табуляції.

Успішні сценарії вже перевіряли збереження книги й номера, початковий статус `Available`, а також можливість двох примірників однієї книги з різними номерами. Однак цей тест не перевіряє й не доводить заборону дублювання інвентарного номера: глобальна унікальність ще не реалізована.

## Green

До конструктору `BookCopy(Book book, string inventoryNumber)` додано перевірки:

- `null`-книга спричиняє `ArgumentNullException(nameof(book))`;
- порожній або пробільний `inventoryNumber` спричиняє `ArgumentException` із повідомленням `"Inventory number cannot be empty."` та `nameof(inventoryNumber)`.

Решта поведінки збережена: властивості `Book`, `InventoryNumber` і `Status` залишаються, а початковий статус — `Available`.

Повторний запуск етапу Green через Test Explorer підтвердив: усі 28 тестів усьому рішенні успішні, 0 помилок, 0 пропущених. Це означає 27 успішних тестів у `Library.UnitTests` і 1 успішний шаблонний тест у `Library.IntegrationTests`.

## Refactor

Для поточного коду рефакторинг без зайвих абстракцій не потрібний: конструктор містить лише мінімальні перевірки та присвоєння властивостей. Додаткові helper-и або методи б змінювали просту структуру примірника без потреби.

GitHub Copilot підготував мінімальний enum статусів, модель `BookCopy`, Red-тести та валідації Green-конструктора відповідно до вимог SCRUM-6.
